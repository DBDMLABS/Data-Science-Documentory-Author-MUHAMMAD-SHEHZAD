### Use lowecase letters and underscores
> For both files and folders and avoid from spaces. e.g: `data_preprocessing.py`

> Precauson: Do not use special chracters, only use hyphens or underscore in naming.

### Be Descriptive and specific
> For both files and folders should describe theire content or purpose e.g: `script.py` , `linear_regression.py`

### Use folders to group related files
> Group files logically into folders based on theire functionality or stage in the data science pipeline
> e.g: `data/`, `scripts/`, `models/`, `notebooks/`

### Follow the Consistent naming covention
> Consistancy is a key.\
> if we start with the convention like `verb_noun`(`clean_data.py`)\
> Maintain it throught your project.

### Add versioning when appropriate
> For Version controll, especially when iterating on models, we can append version number or dates.\
> e.g: `model_v1.py`, model_v2.py`, `data_cleanning_v1.py`

### Avoid using names that are reserved python keywords or buit-in-funtions
> Built-in func or keywords like:\
> `list, dict, input, print etc`

### Use limited length
> keep files and filder names short but descriptive to avoid long paths. Use consistant names when possible.\
> e.g: instead of `train_random_forest_classification_model.py` use `train_rf_model.py`

### Avoid names starting from numbers
> e.g: `123_data.py`

### Use plural form of collections
> use plural names of directories/folders containing multiple files:\
> e.g: `scripts/`, `datasets/`

### Use README file
> use readme file in each folder to explain theire contents, struucture and any specific instructions.
