## 1. Data Types

**Purpose:** Data types determine how Python represents information and which operations can be performed on it. In data science, they help distinguish measurements, text, categories, and missing values.

| Term | Meaning / Purpose | Use in Data Science |
|---|---|---|
| Data type | Defines the kind of value an object contains. | Determines valid calculations and transformations. |
| `int` | Whole number, such as `25`. | Counts records, students, or transactions. |
| `float` | Floating-point number, such as `72.5`. | Measurements, averages, and predictions. |
| `complex` | Number with real and imaginary parts. | Signal processing and scientific computing. |
| `str` | Text string. | Names, labels, reviews, and text analysis. |
| `bool` | `True` or `False`. | Filtering records and testing conditions. |
| `list` | Ordered, mutable sequence. | Storing observations or features. |
| `tuple` | Ordered, immutable sequence. | Fixed coordinates and configuration values. |
| `set` | Collection of unique, hashable elements. | Finding distinct categories. |
| `dict` | Insertion-ordered key-value collection. | Representing structured records and settings. |
| `None` | Represents the absence of a value. | Marking unavailable information. |
| `type()` | Returns an object's type. | Inspecting imported values. |
| `isinstance()` | Checks whether an object is an instance of a type. | Validating function inputs. |
| Type conversion | Converts a value from one type to another. | Turning imported numeric strings into numbers. |
| Mutable | Object whose contents can change. | Updating lists and dictionaries. |
| Immutable | Object whose contents cannot change. | Representing fixed values. |
| Indexing | Accesses an item by position. | Retrieving a particular observation. |
| Slicing | Selects a portion of a sequence. | Taking a subset of data. |


> **Remember:** Data type = what kind of value is this?

## 2. Variables

**Purpose:** Variables give names to values so that datasets, calculations, and model settings can be reused.

| Term | Meaning / Purpose | Use in Data Science |
|---|---|---|
| Variable | Name referring to an object. | Stores datasets and results. |
| Assignment `=` | Binds a name to a value. | Saves an average or prediction. |
| Identifier | Valid name for a variable, function, or class. | Makes analysis code understandable. |
| Naming convention | Consistent naming style. | Improves project readability. |
| `snake_case` | Lowercase words separated by underscores. | Names such as `average_salary`. |
| `PascalCase` | Capitalized words joined together. | Class names such as `DataCleaner`. |
| Keyword | Reserved Python word, such as `if`. | Avoids invalid identifiers. |
| Dynamic typing | A name can refer to objects of different types. | Supports exploratory programming. |
| Multiple assignment | Assigns several names in one statement. | Sets analysis parameters together. |
| Unpacking | Assigns collection elements to separate names. | Separates coordinates or returned results. |
| Constant | Value intended not to change, usually uppercase. | Stores fixed thresholds and settings. |
| Local variable | Name defined within a function. | Holds temporary calculations. |
| Global variable | Name defined at module level. | Holds shared configuration when appropriate. |
| Scope | Region where a name can be accessed. | Prevents accidental interference between functions. |
| `global` | Allows assignment to a module-level name from a function. | Occasionally manages shared state; often avoidable. |
| `del` | Deletes a binding or collection item. | Removes unwanted dictionary entries. |


> **Remember:** Variable = a name that refers to a value or object.

## 4. Control Flow

**Purpose:** Control flow determines which instructions run, which records are processed, and when repeated calculations stop.

| Term | Meaning / Purpose | Use in Data Science |
|---|---|---|
| `if` | Runs code when a condition is true. | Selects records above a threshold. |
| `elif` | Checks another condition. | Classifies values into multiple categories. |
| `else` | Runs an alternative block. | Handles remaining observations. |
| Nested `if` | Conditional inside another conditional. | Applies multiple validation rules. |
| Comparison operators | `==`, `!=`, `<`, `>`, `<=`, `>=`. | Filters data using numerical conditions. |
| `and` | Requires both conditions to be true. | Filters on multiple criteria. |
| `or` | Requires at least one condition to be true. | Selects alternative categories. |
| `not` | Reverses a Boolean condition. | Excludes unwanted records. |
| Truthy / Falsy | Values interpreted as true or false. | Checks whether a collection is empty. |
| `for` | Iterates over an iterable. | Processes observations and features. |
| `while` | Repeats while a condition is true. | Iterates until convergence. |
| Iterable | Object that can provide elements for iteration. | Supplies records to loops. |
| Iterator | Produces elements one at a time. | Processes data incrementally. |
| `range()` | Generates integers for iteration. | Controls training iterations. |
| Nested loop | Loop inside another loop. | Compares pairs of observations. |
| `break` | Exits the nearest enclosing loop. | Stops processing when a condition is met. |
| `continue` | Skips to the next iteration. | Ignores invalid records. |
| `pass` | Placeholder that does nothing. | Marks unfinished processing logic. |
| Loop `else` | Runs when a loop finishes without `break`. | Reports an unsuccessful search. |
| Infinite loop | Loop without a natural stopping point. | Supports continuous monitoring when an exit is provided. |
| Ternary expression | One-line conditional expression. | Assigns simple labels. |
| `match` / `case` | Pattern-matching control flow. | Handles different input formats. |
| Short-circuit evaluation | Stops evaluating when a Boolean result is determined. | Avoids unnecessary or unsafe checks. |


> **Remember:** `if` decides; `for` iterates; `while` repeats; `break` stops; `continue` skips.

## 8. Exceptions

**Purpose:** Exception handling helps programs respond to invalid data, missing files, and unexpected failures.

| Term | Meaning / Purpose | Use in Data Science |
|---|---|---|
| Exception | Error or unusual event during execution. | Signals processing problems. |
| Exception handling | Code responding to exceptions. | Makes data pipelines more robust. |
| `try` | Contains code that might fail. | Attempts data conversion. |
| `except` | Handles a matching exception. | Responds to invalid input. |
| `else` | Runs when the `try` block succeeds. | Processes validated values. |
| `finally` | Runs when leaving exception handling. | Releases resources or logs completion. |
| `raise` | Manually triggers an exception. | Rejects invalid model parameters. |
| `as e` | Binds a caught exception to a name. | Records error details. |
| Custom exception | Programmer-defined exception class. | Represents domain-specific data errors. |
| `Exception` | Base class for most ordinary exceptions. | Handles unexpected errors at suitable boundaries. |
| `ValueError` | Value inappropriate for an operation. | Handles invalid numerical input. |
| `TypeError` | Inappropriate type for an operation. | Detects strings passed to numerical functions. |
| `ZeroDivisionError` | Division or modulo by zero. | Handles invalid ratios. |
| `IndexError` | Invalid sequence index. | Detects out-of-range observations. |
| `KeyError` | Missing dictionary key. | Detects absent record fields. |
| `NameError` | Referenced name not found. | Finds undefined variables. |
| `AttributeError` | Requested attribute unavailable. | Finds incorrect object usage. |
| `FileNotFoundError` | Requested file not found. | Handles missing datasets. |
| `ImportError` | Module or item cannot be imported. | Diagnoses import problems. |
| `ModuleNotFoundError` | Requested module cannot be found. | Detects missing dependencies. |
| `AssertionError` | Assertion evaluates to false. | Checks assumptions during development. |
| Traceback | Shows where an exception occurred. | Helps debug analysis code. |

### Example

```python
raw_values = ["10", "20", "unknown", "30"]
clean_values = []

for value in raw_values:
    try:
        clean_values.append(float(value))
    except ValueError:
        print("Skipping invalid value:", value)

print(clean_values)
```

> **Remember:** `try` = attempt; `except` = handle; `else` = success; `finally` = cleanup.

| `"w"` | Write mode; overwrites existing content. | Saves processed results. |

| `"b"` | Binary mode. | Reads images and other binary data. |
| `"+"` | Enables reading and writing. | Supports file updates when appropriate. |
| `read()` | Reads file contents. | Loads a small text dataset. |

| `seek()` | Changes the file position. | Returns to the beginning of a file. |

### Example: Read a CSV file

```python
import csv

with open("students.csv", "r", newline="", encoding="utf-8") as file:
    reader = csv.DictReader(file)
    for row in reader:
        print(row["Name"], row["Age"])
```

### Example: Write a JSON file

```python
import json

results = {"total_students": 100, "average_score": 82.5}

with open("results.json", "w", encoding="utf-8") as file:
    json.dump(results, file, indent=4)
```

> **Remember:** `r` = read; `w` = overwrite; `a` = append; `x` = create; `b` = binary.

## 10. Imports and Modules

| Standard library | Modules distributed with Python. | Uses `math`, `csv`, `json`, and `statistics`. |
| Third-party module | Module provided by an external package. | Uses NumPy and scikit-learn. |

## 12. Virtual Environments

**Purpose:** Virtual environments isolate each project's Python installation and packages to reduce dependency conflicts and improve reproducibility.

| Term | Meaning / Purpose | Use in Data Science |
|---|---|---|
| Virtual environment | Isolated Python environment. | Gives each project separate dependencies. |
| `venv` | Built-in virtual environment module. | Creates isolated environments. |
| Environment isolation | Separates project dependencies. | Runs projects needing different package versions. |
| Dependency conflict | Incompatible package version requirements. | Explains environment-specific failures. |
| Interpreter | Program that executes Python code. | Selects the Python used for an analysis. |
| Activation | Adjusts the shell to use an environment. | Directs commands to the intended environment. |
| `deactivate` | Exits an activated environment. | Returns to the previous shell environment. |
| Environment directory | Folder containing environment files. | Keeps project dependencies together. |
| `site-packages` | Directory for installed Python packages. | Stores analytical libraries. |
| Reproducibility | Ability to recreate a working environment. | Supports collaboration and repeatable experiments. |
| `.gitignore` | Lists files and folders Git should ignore. | Excludes local environments and generated files. |
| `python -m` | Runs a module with a selected interpreter. | Runs `pip` or `venv` with the intended Python. |

### Example: Create and use an environment

```bash
# Create an environment
python -m venv .venv

# Activate on Windows (Command Prompt)
.venv\Scripts\activate

# Activate on macOS / Linux
source .venv/bin/activate

# Install packages in the active environment
python -m pip install numpy pandas matplotlib

# Save dependency versions
python -m pip freeze > requirements.txt

# Leave the environment
deactivate
```

### Recommended `.gitignore`

```gitignore
.venv/
__pycache__/
*.pyc
```

> **Remember:** Create → Activate → Install → Record dependencies → Deactivate.
